# 本家1.4.0との比較・対応

この文書のローカル測定・確認結果は、Pre6の変更を統合する前の作業ツリーの記録です。Pre7の最終コミットは全OS CIで改めてビルド・測定します。公開リリースの結果はリリース本文を参照してください。

比較対象は本家Meltype v1.4.0、コミット `46db6ca2f941eb9580f4d5ed103ee0bee71111c7`。Rustへ必要な機能を移植したもので、本家の履歴全体をマージした記録ではありません。変更前からの作業ツリーの変更を保持しています。

## 今回の変更

| 項目 | 対応 |
| --- | --- |
| ChromeOSの半角/全角 | JISキー・Alt+Backquoteで日本語と半角英数を切替。未確定文字の確定、長押し、失敗時の再試行を含む |
| 候補操作 | PageUp/PageDown、数字キーでの候補選択をオフにする設定、文節操作後のF6〜F10 |

| 切替キー一覧 | Windowsのキーボード方式で複数登録、旧設定とプロファイルの移行、競合の通知。TSFは既存の切替方式を使う |
| 本家設定の読み込み | 修飾キーの数値と名前（`Alt`、`Control, Alt`など）の両形式に対応 |
| 語句・判定 | 辞書の追加と修正、`^`の文節頭限定、`|`の文節区切り、Androidwa・kamiwoA4などの判定 |

## WindowsのZenzai

Windows TSFで`UseZenzai`を有効にし、利用者が用意したllama-serverとzenz GGUFの場所を指定します。モデルは同梱しません。

起動は非同期で行い、起動中・短く文脈のない読み・失敗時は従来の変換器を使います。1入力要求内の複数の日本語区間でAI待機時間を共有し、合計400msまでに制限します。遅延後は5秒間利用を休み、起動失敗は5分から最大1時間まで間隔を空けて再試行します。文脈は最大100 UTF-16単位、結果のキャッシュは256件です。

OFF・パス変更は次のTIP要求時に反映します。待機中に設定を変更しただけで即停止する通知には未対応です。専用Jobにより、所有プロセスの強制終了時もモデルの子プロセスを終了します。13件の関連試験でHTTP・遅延・不正応答・キャッシュ・文節割当・実子プロセスの終了を確認しています。実モデルの精度・速度、実IMEでの入力確認は未実施です。

## 検証の範囲

ChromeOSは実WASMと模擬IME APIで半角/全角、英数入力からの復帰、候補・確定・再試行、AI設定除去、文節区切りを検査します。ChromeOS実機での確認とは別です。

Windowsの専用GUI試験では旧切替設定の移行と日本語確定まで確認しました。140文字の全体受入は未完了です。その試験で見つかった背景ウィンドウのfocusイベントによる入力破棄を修正し、専用Win32ウィンドウの回帰試験を追加しました。修正後のGUI再試験は未実施です。

本家のC#実行ファイルから設定120ケースの期待値を採取しています。旧1.3.0の期待値も別ファイルとして保持します。再生成は次のコマンドで行います。

```powershell
python tools/parity/v130/regenerate.py --baseline 46db6ca2f941eb9580f4d5ed103ee0bee71111c7 --settings-only
```

候補・設定・OS連携の全組合せで完全同等であることを示す検証ではありません。機能の移植、各打鍵の一致、実IMEでの動作、処理速度を区別して記録します。

速度比較は[共通Coreの測定手順](../tools/performance/windows/README.md)を使います。AI・外部変換器・描画を除いたキー処理とJSON生成の測定であり、アプリ全体の速度や全OSでの優位を示しません。

## 2026-10-30の統合前ローカル速度比較

Windows 11の同じPCで、本家1.4.0のC# NativeAOT、Flash Pre3、今回の作業ツリーをRust Releaseで測定しました。Rust両版は同じコンパイラーを使用し、各版の同梱辞書を維持しています。各条件は2回の慣らし後に5試行、実行順を入れ替えて3巡、計15試行です。

本家と確定・途中表示が一致したのは21/21条件。その全21条件で今回の中央値が短く、入力列全体の処理時間は本家の11.7〜48.3%（約2.1〜8.6倍の速さ）でした。ソース・バイナリの測定中の不変を確認しています。

| 入力条件 | 本家1.4.0 (ms) | 今回 (ms) | 今回 / 本家 |
| --- | ---: | ---: | ---: |
| short_japanese | 4.805 | 1.087 | 0.226 |
| short_mixed | 2.977 | 1.103 | 0.370 |
| short_english | 0.518 | 0.145 | 0.280 |
| japanese_256 | 3926.445 | 1227.060 | 0.313 |
| mixed_256 | 3766.079 | 901.433 | 0.239 |
| english_256 | 3942.591 | 460.482 | 0.117 |

旧Flash Pre3との比較では、途中状態が一致した21条件のうち、今回が速かったのは1条件、遅かったのは20条件です。最大で約22%遅い条件が残ります。ソース・辞書・依存関係が異なるため、今回の変更だけの影響として切り分けた結果ではありません。

全測定値・ハッシュと10枚の箱ひげ図・比較表はローカルの検証用フォルダーに保存しています。公開リリースには、最終CIで再測定した結果を本文に掲載します。CPU・RAMの観測はプロセス起動・辞書作成・慣らし・出力を含み、キー処理の区間とは異なります。

追加の98入力の診断では、確定97/98、途中表示93/98が一致しました。点数判定の`kamiwoA4`は本家の`かみをあ4`に対して、Flashは`かみをA4`を保持します。`huusoku6me-toru`・`e2e`などには入力途中の差が残ります。この診断結果は速度の集計には使用していません。
